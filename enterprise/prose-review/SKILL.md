Review a document against the prose standard below. The standard and the checks are written out here, so the review depends on no personal configuration.

Target: $ARGUMENTS

If no path is given, ask which file. If the argument is raw text and not a path, review it in place and skip the apply step. If `--apply` is present, make the edits without asking first. Otherwise report findings and ask before editing.

If the path is a folder, review every `.md` file under it. Each file is its own review: never compare one file with another, carry a finding across files, or cite another file in a finding. By default, review the files one at a time. With `--agents`, launch one subagent per file and give each only its file path, the flags, and an instruction to follow this skill; each agent edits only its own file. Report findings grouped by file.

Review only the target. Do not check its claims against other documents unless asked. Leave quoted material, code, identifiers, and links as written.

## Standard

Write like a competent English major, with Strunk and White as the reference.

- Omit needless words. Every sentence should survive the question "what does this add?"
- Write with nouns and verbs, not adjectives and adverbs.
- Use definite, specific, concrete language. Prefer the standard word to the offbeat.
- Do not overwrite, overstate, or affect a breezy manner.
- Vary sentence structure on purpose. Repeated syntax is a signature, and a signature applied to every sentence is noise.
- Treat emphasis as scarce: bold text, one-line paragraphs, sentence fragments, and closing zingers mark what matters only when they are rare.

## Procedure

1. Read the whole file and record the word count.
2. Run every check below.
3. Report findings in order of reader cost, not check number, and group findings that share a cause. Tag each fix **correct**, **delete**, **narrow**, or **add**. List corrections in one line apart from the style findings. Name what to keep: a flagged construction that earns its place stays, and the report says so. Skip clean checks rather than writing "no instances found" for each; say in one line which checks came back clean. State the projected word reduction. A cut of about a quarter is a reasonable expectation; report the actual figure without forcing it.
4. Ask before editing, unless told to apply. `--apply` covers corrections, deletes, and narrowings only. An add waits for explicit approval. Preserve the argument and the author's voice. This is a revision pass, not a rewrite. If a replacement changes what the sentence asserts, do not make it. Flag it as a question instead.
5. Edit one construction at a time so each change is reviewable. Report the word count before and after. Do not summarize the changes in prose, since the findings already said what changed.

## Checks

A named check can be tested against the text. A disposition such as "write better" cannot. For each hit, report `file:line`, the quoted text (under 15 words), the name of the failure, and a specific replacement. A finding you cannot phrase as a diff is not a finding.

0. **Mechanics.** Misspellings, wrong words (their/there, affect/effect, form/from), doubled or missing words, broken subject-verb agreement, and inconsistent spelling or capitalization of a proper noun. Run this check first, on every line. Tag each fix **correct**.
1. **Contrast scaffolds.** "Not X, but Y" and its variants: "X isn't the problem; Y is", "X does not A. It does B." A scaffold earns its place when both halves carry meaning the reader needs. It does not when the negated half is a straw position invented to be knocked down. Flag the second kind. Leave the first, and say you left it.
2. **Announced significance.** "It's worth noting", "the interesting thing here is", "and that matters because", "worth flagging", "this is where it gets X". Delete the announcement and let the next sentence carry itself.
3. **Pseudo-headers.** A paragraph-opening sentence that names the paragraph's topic without asserting anything about it. Delete it. If the paragraph loses only a label, the sentence was a pseudo-header.
4. **Question restatement.** An answer's setup that restates what was asked. Delete it.
5. **Self-reference.** The writer naming their own perspective, stake, or limitations. Uncertainty about a claim is often load-bearing, and the first person carrying it rarely is. Convert "I have not tested this" to "Untested", and "the findings I recall are qualified" to "The findings are qualified". Keep the epistemic content and drop the narrator.
6. **Padded lists.** Three items where two carry the point, or four where two do. Identify which items do work and which fill a rhythm.
7. **Rhythm signatures.** Repeated syntax across consecutive paragraphs or sections: aphoristic paragraph closers, category-membership connectives ("X belongs here too", "Y fits the same account"), superlative rankings ("the clearest case", "the strongest example"). Any one is fine. Five in a row is a tic. Count them, name the shape, and cut enough that the survivors land.
8. **Em-dash reversals.** Count occurrences and divide by word count. Above roughly one per 250 words, the dash has become rhythm and not an aside. Keep genuine parentheticals. Convert the rest to colons, periods, or nothing.
9. **Emphasis budget.** List every instance of bold text, one-line paragraphs, sentence fragments, and closing zingers. Allow at most one emphatic move per section, often zero. Keep the strongest one or two.
10. **Cut pass.** Walk the transitions and setup sentences. Delete each one and check whether anything was lost. Usually nothing was.
11. **Meta-commentary.** A body sentence about the document rather than its subject: "This doc describes…", "Draws on…", "New here.", "Not yet reviewed." Delete it, unless the reader needs the information and nothing else in the document carries it.
